# 6G-SEC-MCP: Autonomous Edge IDS/IPS via Model Context Protocol

Experimental evaluation framework for a Master's research project in Computer Science (IME-USP) investigating **LLM-based Intrusion Detection and Prevention Systems (IDS/IPS)** at a 5G/6G Multi-Access Edge Computing (MEC) User Plane Function (UPF) node.

The testbed compares two architectural paradigms under identical network and attack conditions:
1. **Baseline Direct-Execution IDS (`ids_baseline.py`)**: Reads raw Open vSwitch (OVS) telemetry logs, embeds `ovs-ofctl` documentation directly into the prompt, and executes raw CLI strings generated by the LLM via the network adapter.
2. **Proposed MCP-Mediated IDS (`mcp_server.py` + `ids_mcp_client.py`)**: Enforces local Client-Server isolation using the **Model Context Protocol (MCP)**. The MCP server filters background UE noise into a compact JSON Resource (`telemetry://ovs/aggregated_flows`) and exposes a single sandboxed tool (`block_ip(target_ip)`) with RBAC, strict IPv4 regex validation, and protected-IP whitelisting.

---

## Distributed Infrastructure Topology

- **Host A (Edge / MEC Server - High RAM)**: Runs the Docker Compose topology (`ovs-node`, `traffic-gen`, and `agent-env`).
- **Host B (GPU Workstation / Local Notebook)**: Runs the LLM inference engine (Ollama on port `11434`).
- **Reverse SSH Tunnel (Host B -> Host A)**:
  ```bash
  ssh -N -R 11434:localhost:11434 user@host-a-address
  ```
  Inside `agent-env`, requests to `http://host.docker.internal:11434/v1` traverse the reverse SSH tunnel to Host B.

## Quick Start & Execution Guide

### 1. Configure Environment
```bash
cp .env.example .env
```

### 2. Build and Launch the MEC Container Topology (Host A)
```bash
docker compose up -d --build
```

### 3. Trigger Attack Vectors (inside `traffic-gen`)
Benign traffic (`start_benign_traffic.sh`) starts automatically in `traffic-gen`. To manually launch attacks:
```bash
# Volumetric TCP SYN Flood
docker exec -it traffic-gen /scripts/attack_syn_flood.sh

# Low-Rate Slowloris DDoS
docker exec -it traffic-gen /scripts/attack_slowloris.sh

# Aggressive Nmap Reconnaissance Scan
docker exec -it traffic-gen /scripts/attack_port_scan.sh
```

### 4. Run the IDS Evaluations (inside `agent-env`)
```bash
# Run Baseline Direct-Execution IDS (e.g., 10 iterations)
docker exec -it agent-env python ids_baseline.py --iterations 10 --interval 5

# Run Proposed MCP-Based IDS (e.g., 10 iterations)
docker exec -it agent-env python ids_mcp_client.py --iterations 10 --interval 5
```

### 5. Inspect Collected Metrics
All experimental iterations are appended to `metrics_results.csv` with millisecond-precision `time.perf_counter()` measurements:
- `deployment_delay_ms`: End-to-end delay from telemetry inspection to switch rule installation.
- `inference_latency_ms`: LLM network round-trip latency to Host B.
- `signaling_overhead_bytes`: Total control-plane byte count (prompts, metadata, and MCP JSON-RPC round-trips).
- `prompt_tokens`, `completion_tokens`, `total_tokens`: Token consumption comparison (raw logs vs. filtered JSON resource).
- `cpu_peak_percent`, `ram_peak_mb`: Edge container resource overhead sampled via `psutil`.
